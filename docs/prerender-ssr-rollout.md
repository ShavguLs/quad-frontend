# Prerender and SSR rollout

Quaduni keeps build-time prerendering for public SEO routes and treats Django as the canonical sitemap owner.

## Current source of truth

- Public static HTML metadata is generated by `frontend/scripts/prerender-routes.mjs`.
- Production sitemap ownership is backend-only at `https://api.quaduni.com/sitemap.xml`.
- `frontend/public/robots.txt` points crawlers at the backend sitemap so the frontend artifact does not need to publish a second sitemap.

## Covered prerender routes

- Static routes: `/`, `/books`, `/reviews`, `/community`, `/terms`
- Dynamic routes: `/book/:id`
- Private routes stay prerendered as `noindex,nofollow` shells for SPA navigation only.

## Build outputs

- `npm run build` generates route HTML under `frontend/dist/`
- `npm run build` also writes `frontend/dist/prerender-report.json`

The prerender report records:

- total prerender duration
- prerendered book count
- sample generated book paths
- the active sitemap owner and sitemap URL
- whether current build size or duration crosses the rollout guardrails

## Guardrails

- Full book prerender remains the default while `prerenderedBookCount <= 750`
- Full book prerender remains the default while `durationMs <= 180000`
- If either threshold is exceeded, switch planning toward tiered prerendering or hybrid server-side meta injection before full SSR

You can override thresholds during CI with:

```bash
SEO_MAX_FULL_BOOK_PRERENDER_COUNT=750
SEO_MAX_FULL_BOOK_PRERENDER_DURATION_MS=180000
```

## Validation

Run the frontend build and inspect the generated report:

```bash
npm run build
```

Then verify:

- `frontend/dist/index.html`
- `frontend/dist/books/index.html`
- `frontend/dist/reviews/index.html`
- `frontend/dist/community/index.html`
- `frontend/dist/terms/index.html`
- one or more `frontend/dist/book/<id>/index.html`
- `frontend/dist/prerender-report.json`

The prerender script fails the build if required metadata is missing from public route HTML.

## When to revisit SSR

Re-open SSR only when one or more of these are true:

- request-time rendering is already supported in the deployment runtime
- full-catalog prerender time becomes operationally expensive
- metadata freshness must update immediately without a rebuild
- SEO requirements expand to many more dynamic route types

Prefer a hybrid step first, such as server-side meta injection, before a full framework migration.
